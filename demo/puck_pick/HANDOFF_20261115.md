# 인수인계: 서 있는 퍽 집기 + 적재 (2026-11-15)

읽는 사람: 이 작업을 이어받는 다음 세션. 코드 위치는 `~/craft`, 사용자 호칭과 말투 규칙은 `~/.claude/projects/-home-craft-craft/memory/`에 있다.

## 1. 한 줄 요약

`python3 ~/craft/demo/puck_pick/execute.py --find choi` 한 번이면, 박스 위 2번~8번 칸 사이 아무 데나 서 있는 프리즘을 찾아서 집고 클락 슬롯 12에 넣고 노미널로 돌아온다. 실물에서 1, 2, 5, 8번 칸, yaw 0도와 ±30도까지 확인했다.

## 2. 용어 (사용자와 정한 이름, 이대로 쓸 것)

| 이름 | 코드 | 뜻 |
|---|---|---|
| 노미널 | nominal | 출발·복귀 자세. 어퍼캠 촬영 |
| 비아 | via | 노미널과 작업 사이 경유 자세 |
| 관측 자세 | wait | 퍽 위 약 70 mm(dice 75 mm 자세). 그리퍼캠 촬영 (yaw, 퍽 중심) |
| 준비 자세 | approach | 티칭한 `stand_above_c*` + 3 mm. 여기서 한 번에 하강 |
| 잡기 자세 | grasp | 티칭한 `stand_grasp_c*`. 조 닫기 |
| 들기 자세 | lift | 퍽 잡고 관측 자세 높이로 |

칸 번호는 로봇 기준(로봇 뒤에서 앞을 봄)이다. 1 2 3 = 먼 줄, 4 5 6 = 가운데, 7 8 9 = 로봇 쪽. 왼쪽이 LM 모터 반대쪽이다.
좌표: x = 로봇 정면(+ = 로봇에서 멀어짐), y = 로봇 좌측(+ = LM 모터 반대쪽 = slide -).

## 3. `--find` 순서 (execute.py `find_steps`, `find_step`)

1. 노미널에서 어퍼캠 촬영 (`tools/realsense_check/build/upper_puck`, C++, YOLO + depth, 약 0.3초). 앞뒤 `UPPER_AHEAD_BIAS_MM` 20.1, 좌우 `UPPER_LATERAL_BIAS_MM` -12.0을 빼고, 47.5~177.5 mm 안의 최고 점수 퍽을 고른다.
2. 비아 → 그리퍼 풀 오픈 → 관측 자세. 앞뒤는 세 줄(8/5/2번) 보간, 좌우는 LM.
3. 그리퍼캠 촬영 (`build/grip_yaw`, C++, depth 640x360 10프레임, 약 1.3초) → yaw와 퍽 중심. `stand_cal.json`의 칸별 기준점과 2x2(카메라 mm / 팔 mm)를 보간해 LM과 앞뒤를 보정한다. 25 mm를 넘으면 멈춘다.
4. roll = 관측 roll + (yaw − 칸별 yaw 기준). 사각이라 yaw는 [-45, 45).
5. 준비 자세 → 한 번에 하강(2초) → 잡기 자세 → 조 닫기 → 들기 → 클락 → carry via → 슬롯 → 놓기 → carry via → 비아 → 노미널.
6. 준비 자세와 잡기 자세 LM이 레일(-43.0~62.7 mm)을 벗어나면 내려가지 않고 멈춘다.

판마다 `demo/puck_pick/runs/find_MMDD_HHMMSS/`에 기록이 남는다. `log.json`(어퍼캠 값, 보정값, 들어간 보정표 값, 사용자 평가 `user_eye`)과 잡기 자세 컬러 사진 2장(조 열림/닫힘), 카메라 원본이다. `--no-record`를 붙이면 사진을 찍지 않는다.

## 4. 보정 (튜닝하는 곳: execute.py 상단의 표들)

사용자가 판마다 "직전 설정 대비 TCP 중심이 퍽 중심에서 어디에 있었는지"를 알려준다. **그 값을 직전 설정에 그대로 더하고 뺀다. 평균 내지 않는다.** 방향이 애매하면 한 번만 물어본다.

| 표 | 기준 | 현재 값 |
|---|---|---|
| `STAND_X_FIX_TABLE` | 보정 후 퍽 앞 거리 | 42.1→-10, 97→-2, 157→-10 |
| `STAND_Y_FIX_TABLE` | 앞 거리 | 42.1→+4, 97→0 |
| `STAND_YAW_X_FIX_TABLE` | yaw (부호 있음) | -26→+6, 0→0, +26→+3 |
| `STAND_YAW_Y_FIX_TABLE` | yaw, 앞 거리별 | 97: -26→+1, +26→+4 / 157: -26→+1(미실측), +26→+2 |
| `STAND_LM_Y_FIX_TABLE` | LM 위치 | -40→-2.4 (레일에 걸린 1판 기준, 신뢰 낮음), 12.2→0 |
| `STAND_GRASP_Y_FIX_M` | 전체 | -0.010 (모터 쪽 10 mm, 어깨 조인 뒤) |
| `STAND_APPROACH_UP_MM` | 준비 자세 높이 | +3 mm |
| `STAND_APPROACH_X_FIX_TABLE` | 준비 자세만 | 0 |

모든 값은 표 사이에서 직선 보간하고, 표 밖은 끝값을 쓴다.

## 5. 카메라

- **그리퍼캠 yaw** (`grip_yaw.cpp`, 분석용 `grip_yaw.py`): 태그가 아니라 depth로 잰다(태그가 돌아가 붙어 있을 수 있다는 사용자 지적). RANSAC 박스 면 → 윗면 높이대(48~72 mm) 점 → 광선을 윗면 평면에 투영 → 최소 사각형. 보정 `grip_yaw.json`은 offset -2.39, sign -1이다.
  - depth는 반드시 640x360이다. 1280x720은 26 cm보다 가까운 것을 못 보는데 윗면이 약 22 cm다.
  - 덩어리는 윗면 높이대로만 나눈다. 12~75 mm로 나누면 옆의 낮은 물체가 붙는다(20:19 실패 원인).
  - 걸러내는 조건: 윗면 52~68 mm, 한 변 20~38 mm, 흔들림 6도 이하, 절반 이상의 프레임.
- **잡기 자세에서는 그리퍼캠 depth가 안 잡힌다.** 너무 가깝거나 조에 가린다. 그래서 최종 보정은 사용자의 눈으로 한다.
- **어퍼캠** (`upper_puck.cpp`): 카메라 자세는 `upper_cam_pose.txt`(puck_locate.camera_pose()에서 뽑은 값)다. 앞뒤 오차는 칸마다 +9~+27 mm로 들쭉날쭉해서 평균만 빼고, 나머지는 그리퍼캠이 고친다.
- **`stand_cal.json`**: `--standcal --cell 2|5|8`로 만든다. 사용자가 잡기 자세에서 퍽을 손으로 맞추면 조가 닫혔다 열리고, 관측 자세에서 기준 촬영과 LM ±10, 앞뒤 ±10 촬영을 하고, 노미널에서 어퍼캠 촬영을 한다. 5번은 18:03, 2번과 8번은 16:26/16:28(어깨 조이기 전) 값이다. 2번과 8번 재보정은 시야에 물체가 들어와 실패했다.

## 6. 티칭한 자세 (teach.yaml, 같은 이름이면 마지막 것을 쓴다)

- `stand_grasp_c2/c5/c8`: 잡기 자세. LM까지 포함한다(그리퍼가 휘어 있어서). c2는 roll +26에서, c5/c8은 roll 90(yaw 0)에서 찍었다. 다른 yaw에서는 roll만 바꾼다.
- `stand_above_c2`(20:18), `stand_above_c5`(17:04), `stand_above_c8`(17:08): 준비 자세. 팔 각도만 쓰고 LM은 잡기 자세 값을 쓴다.
- dice 자세는 `dice_place_c<칸>_*`로 이름을 바꿨다(옛 이름 p13~p18). `stand_grasp_c2_DROPPED_do_not_use`는 어깨 폴트로 떨어진 자세다.
- teach.py는 조그 목표와 실제가 1.5도 넘게 다르면 저장을 거부한다(폴트 대비).

## 7. 알게 된 것 (다시 겪지 말 것)

- **URDF 모델은 툴 각도에서 실제와 다르다.** 계산한 잡기 자세는 툴이 로봇 안쪽으로 말리고, 먼 줄(2번)은 모델상 특이점이라 수직 이동이 계산되지 않는다. 그래서 자세는 티칭, 작은 상대 이동만 모델로 한다.
- 대각선 하강의 원인은 준비 자세가 잡기 자세 바로 위가 아니었기 때문이다. 바로 위에서 한 번에 내려가면 곡선은 약 2 mm라 조각낼 필요가 없다.
- 사각 프리즘에서 ±45도는 +45/-45가 판마다 바뀌어 roll이 90도 반대로 돈다. 실험에서는 피한다. "60도 돌림" = -30도다.
- roll 회전 방향과 배율(`STAND_ROLL_PER_YAW` 1.0)은 실물에서 확인했다(자동 0.4416 vs 티칭 0.4503 rad).
- 어깨를 조이면 좌우 보정이 크게 바뀐다(+3 → 0 → -10 mm).
- 카메라 처리는 C++로 한다. Python으로는 3초가 걸려 대기 중 어깨가 버티지 못했다.

## 8. 오늘 바꾼 설정 (커밋 안 함, `git status` 참고)

## 11. 세션 재개 후 추가: 미션 집기 연결

위 1~10절 이후 이전 세션에서 누운 프리즘 `--lie --cell 2|5 --pick`이 추가됐다.
최신 요청은 **이 집기 흐름을 프로젝트 미션에 연결하고, 실험에서 생략한 28cm 후진 / 재도킹을 실제 주행으로 대체**하는 것이다. 실린더 작업은 그다음이다.

이번에 연결한 것:

- `mission_master`의 PickPuck은 더 이상 0.5초 후 가짜 성공을 내지 않는다. `/mission/pick_request` → 새 `puck_picker.py` → 실제 executor 종료 결과를 기다린다.
- `execute.py --planning`은 `/planning/pick_step`으로 단계들을 보낸다. `planning_master`가 명령 번호, hold, watchdog, STOP을 관리하고 `/planning/pick_step_result`로 원 요청 번호의 결과를 돌려준다.
- 누운 퍽: 8번에 놓고 상승 → **0.28m 후진** → 팔꿈치/손목/LM → 어깨 절반(roll 유지) → 어깨 나머지+roll → **같은 박스 재도킹** → 다시 잡기 → 지정 슬롯 적재 → carry via → 비아 → 노미널.
- 28cm 후진 요청은 장애물이 있다고 짧게 줄이지 않는다. 재도킹은 28cm 뒤에서 LiDAR로 접근한 뒤 어퍼캠으로 마무리하며, 별도 stage 위치로 돌아가지 않는다.
- 프로젝트 카메라 드라이버(`uppercam_bridge`, `realsense_processor`)에 촬영 중 USB 사용을 넘겨주는 `pick_pause`/`pick_paused` 경로를 추가했다. 촬영마다 일시 정지 확인 후 C++ 프로그램을 실행하고 복귀시킨다. 갱신이 끊긴 일시 정지는 2초 후 만료한다.
- 실패/취소는 비정상 종료로 전달하고, 미션 집기에서 조를 닫았는데 grasped가 아니면 중단한다.

사용법은 `src/craft_planning/README.md` 마지막 절에 있다. 프로젝트 노드들을 새 빌드로 재시작하고, 도킹/노미널 상태이며 planning이 `Run.AwaitRequest`일 때 단독 확인하는 명령:

```bash
python3 ~/craft/demo/puck_pick/execute.py --planning --lie --cell 5 --pick --box S1 --slot 12 --auto
```

`mission:=true`는 `puck_picker.py`도 띄운다. `mission.yaml`의 `pick_modes`는 수집 슬롯 순서대로 `find`, `lie2`, `lie5`를 지정한다(생략하면 모두 find). **drive_only는 기존 true를 유지했다.** 누운 퍽 임의 위치 탐지는 아직 없고, 2/5번 티칭을 사용한다. Observe/Place/Verify와 퍽 ID 연결은 기존 skeleton이므로 전체 대회 미션 완성으로 오해하지 말 것.

검증: craft_sensors/planning/bringup 빌드 통과, 누운 퍽 5번 전체 드라이런 통과, 새 ROS 모의 통합 테스트 5개 및 adapter 테스트 3개 통과, 기존 state_machine/planning_config/mission_logic/mission_fsm C++ 테스트 4묶음 통과. ROS 테스트는 별도 domain에서 가짜 제어기를 사용했다. **실물 모터/카메라 전환/재도킹은 아직 실행하지 않았다.** 다음 단계는 실제 도킹 상태에서 이 단독 흐름을 검증하는 것이다.

**standing 우선, 같은 자세라면 로봇에 가까운 순서. 색상·모양·검출 점수가 이 우선순위를 바꾸지 않는다.**

- `demo/puck_pick/pick_policy.py`: 후보 파싱/정렬. 거리는 보정된 base_link 평면거리. 박스 영역(앞 0~205mm, 좌우 ±102.5mm), confidence >=0.4. 현재 선택 대상이 작업 범위 밖이면 낮은 순위로 건너뛰지 않고 중단한다.
- `upper_puck.cpp`: 주변 depth에서 박스 면을 추정(모든 검출 박스 제외), 퍽 윗면95%높이−박스 높이로 prism 자세를 판별. 45~75mm standing / 20~40mm lying / 나머지 unknown. cylinder는 standing. 출력에 `posture`, `height` 추가; RViz 메시지도 이 값을 사용한다.
- `execute.py --collect`: 노미널에서 새 촬영 → 우선순위 선택 → standing/lying 경로 자동 분기. 이전 `--find`의 최고 confidence 1개 선택도 우선순위 선택으로 교체. 조작용 `--lie --cell`은 유지.
- `mission_master`의 생략 모드는 collect로 바뀜. 요청에 남은 개수 추가 → adapter가 `--expected-pucks 2|1` 전달. 첫 집기2개, 두 번째1개를 확인하며, 미검출/초과/자세unknown은 재촬영1회 후 실패. 한 판 성공 후 다음 pick은 무조건 새로 촬영한다.
- `grip_yaw`: 지정 자세/목표 중심 주변만 읽고, 나머지 퍽 예상 위치 쪽 덩어리를 배제한다. cylinder `--no-yaw`는 중심만 읽고 yaw 흔들림 검사를 생략하며 roll을 돌리지 않는다.
- 선택 후보·이유는 `log.json selection` 및 `PICK POLICY` 로그에 남는다.
- 누운 퍽은 기존 2/5번 티칭 주변20mm만 자동 연결. 앞뒤/LM local correction 최대25mm, 앞뒤는 완전한 해가 안 나오면 내려가지 않는다. 임의 위치 전체 lying 작업/실린더 집기/어퍼캠 2개 자세판별 실물검증은 아직 필요하다.
- 빌드: craft_planning, upper_puck, grip_yaw 통과. 정책·adapter·RViz 테스트30개와 executor 분기 테스트4개 통과. 합성 depth 2개에서 좌/우 목표선택, 애매한 경쟁목표거절, 원기둥 중심전용4조건 통과. 모터는 움직이지 않았다.
