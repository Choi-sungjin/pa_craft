# 자이로 배율 실험

**상태: 1차 실시 (2026-10-31, `gyro_spin.py`, 5바퀴 CCW·CW 각 1회).** 보정 불필요.

| 보드 | CCW | CW | 평균 |
| --- | --- | --- | --- |
| wheel_clock | 0.9994 | 0.9992 | 0.9993 |
| lm_arm | 0.9988 | 1.0004 | 0.9996 |

두 보드 모두 1800°에서 2° 이내(0.1% 미만)라 배율 파라미터는 만들지 않는다. IMU를 기준으로 한
turn_map 계수와 휠 odom 비교는 그대로 유효하다. 같은 회전에서 휠 odom/실제는 CCW 1.015, CW 0.972로
방향별 차이가 있었다(`results.csv`).

두 OpenCR(2018년 보드, MPU-9250)의 자이로 배율(scale factor) 오차를 보드별로 잰다.
자이로 배율은 IMU가 낸 각속도와 실제 각속도의 비율이다. 1.00이면 정확하다.

## 두 보드 동시: `gyro_spin.py` (2026-10-31)

아래 "먼저 만들어야 할 것" 없이 할 수 있다. control_master가 두 보드의 원시 IMU(`/control/imu/{wheel_clock,lm_arm}`)를
내므로, `test/drive/gyro_spin.py`가 control의 teleop으로 로봇을 돌리면서 두 보드와 휠 odom을 함께 기록한다.

1. 바닥 기준선 테이프에 로봇 정면 표시를 맞춘다. 반경 0.5 m를 비운다.
2. `bro`(control_master)를 띄우고, 다른 터미널에서 `/usr/bin/python3 ~/craft/test/drive/gyro_spin.py`.
3. 회차마다: 3초 정지(오프셋) → 스크립트가 5바퀴에서 45° 모자란 곳까지 돌리고 멈춤 → **`a`/`d`를 눌러 정면 표시를
   기준선에 정확히 맞추고 `c`** → 3초 정지. 실제 회전각이 정확히 1800°이므로 각도를 잴 필요가 없다.
4. 기본 CCW·CW 번갈아 각 3회(`--runs 3`). 회차가 끝나면 로봇이 이미 선 위에 있으므로 Enter로 다음 회차.
5. `results.csv`에 보드별로 한 줄씩 쌓인다. `odom_compare.py --summary`로 보드·방향별 배율과 휠 odom 정확도를 본다.

bag으로 기록한 경우는 `odom_compare.py <bag> --turns auto --residual-deg <잔여각>`(wheel_clock만).
배율 k는 이미 모은 데이터에 곱해서 반영한다(재측정 불필요): `turn_map.py poly --gyro-scale k`로 휠 odom 계수를,
`odom_compare.py <bag> --gyro-scale k`로 WASD 비교를 다시 낸다. 방향별로 다르면 `--gyro-scale-cw`를 함께 준다.

## 왜 필요한가

- **데이터시트 허용 범위**: MPU-9250의 배율 오차는 25 °C에서 ±3%이고, 온도 범위 전체에서는 ±4%다
  ([PS-MPU-9250A-01 r1.1](https://xdevs.com/doc/TDK/MPU-9250_Rev_1.1.pdf)).
- **회전할수록 커지는 오차**: 배율 오차는 회전한 각도에 비례해서 yaw 오차를 만든다.
  3%면 90° 돌 때마다 2.7°, 360° 돌면 10.8°다.
- **두 보드 판정에 영향**: control_master는 두 보드 값의 차이가
  `imu_max_disagreement + imu_max_disagreement_ratio × |회전속도|`를 넘으면 한쪽 보드만 쓴다.
  지금 비율은 8%로, 칩당 ±3%인 두 보드가 최대 6% 다를 수 있다고 보고 정한 값이다.
  두 보드의 배율 차이를 실제로 재면, 이 비율을 낮춰 고장 판정을 더 엄격하게 할 수 있다.
- **급하지 않은 이유**: 2026-10-29 sim(2바퀴, 모서리 제자리 회전 90°×8)에서 ±3% 오차를 넣었다.
  위치 정확도는 그대로였다(평균 0.9–1.1 cm). 회전 중 yaw 오차만 2°에서 최대 3.6°로 잠깐 커졌다가
  1° 이내로 돌아왔다. 0.2초마다 SLAM yaw가 고치기 때문이다. IMU만 쓰면 2바퀴 뒤 13–24°가 틀어진다.
  제자리에서 여러 바퀴 도는 주행 시나리오는 없다.

## 먼저 만들어야 할 것

- [ ] **보드별 각속도 출력**: control_master는 두 보드를 합친 값(`/control/imu/data`)만 낸다.
  보드별 보정된 yaw rate를 디버그 토픽으로 내는 기능이 필요하다.
  또는 control_master를 끈 상태에서 두 OpenCR 시리얼을 직접 읽는 스크립트(`slip_test.py` 방식)를 만든다.
- [ ] **배율 파라미터**: `control.yaml`에 보드별 배율 파라미터(예: `imu_gyro_scale: [wheel_clock, lm_arm]`)를 두고,
  `imu_fusion`에서 바이어스를 뺀 뒤 곱하도록 한다. 아직 구현하지 않았다.

## 절차

1. 새 펌웨어(IMU 7필드)를 두 보드에 올린다(`resetall`). 업로드 직후 5초는 로봇을 움직이지 않는다.
2. 바닥에 기준선 테이프를 붙이고, 로봇 정면에 표시를 해서 기준선에 맞춘다.
3. control을 켜고 2초 이상 정지한다. 로그에 `wheel_clock IMU calibrated`와 `lm_arm IMU calibrated`가
   뜨는지 확인한다. 이때 찍히는 기울기와 바이어스도 기록한다.
4. 제자리에서 반시계 방향으로 **5바퀴** 회전한다. 평소 회전 속도인 `wheel_rotate_angular_speed` 0.6 rad/s를 쓴다.
5. 정지한 뒤 기준선과 로봇 표시 사이의 각도를 잰다. 실제 회전각은 1800° ± 잰 값이다.
6. 보드별 적분 각도를 기록한다.
7. 시계 방향으로 4–6을 반복한다. 방향마다 3회씩 한다.

## 결과 정리

- **배율** = 실제 회전각 / 보드별 적분각. 보드별, 방향별 평균과 편차를 낸다.
- **판정**:
  - 두 보드의 배율 차이가 3%를 넘거나 어느 보드든 1.00에서 2% 이상 벗어나면, 배율 파라미터를 반영한다.
  - 반영한 뒤에는 `imu_max_disagreement_ratio`를 (측정한 차이 + 여유)로 낮춘다.
- **기록할 조건**: 실험 날짜, 보드를 켠 뒤 지난 시간(온도 영향), 기록한 숫자를 이 파일에 남긴다.
