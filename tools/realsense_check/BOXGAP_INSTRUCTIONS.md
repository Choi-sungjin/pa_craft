# 박스 갭 bag 분석 지시서

어퍼캠(상단 D435)으로 박스까지의 거리를 재는 알고리즘을 실측 bag으로 검증하는 작업이다.
이 폴더 하나에 bag, 카메라 파라미터, 코드, URDF가 모두 들어 있다. ROS나 librealsense는 필요 없다.

- `boxgap_1108_1208`에는 카메라만 있다.
- 이후 녹화(`rec_box.sh`)에는 전면 LiDAR bag `lidar/`이 함께 들어 있다. 5.4절을 본다.
- 3절의 시간표는 `boxgap_1108_1208` 기준이다. 다른 bag이면 시간표를 새로 만든다.

## 1. 결과물

1. 프레임별 거리 시계열 `results.csv`: `t_s, xy_mm, dx_mm, dy_mm, ok`
2. 갭별 잔차표. 갭 하나가 한 줄이다(아래 4절).
3. 시계열 그림 한 장 `timeline.png`: x축 시간, y축 dx와 xy. 찾은 정지 구간과 갭 라벨을 표시한다.
4. 짧은 보고: 갭에 따라 오차가 어떻게 변하는지, 구간 안 흔들림(sd), 실패 프레임과 그 원인

보고는 숫자와 파일 경로로 한다. 알고리즘 파라미터나 보정값을 바꿔 본 결과는 기본값 결과를 덮어쓰지 말고 별도 열이나 별도 파일로 둔다.

## 3. 촬영 내용

- 카메라: 어퍼캠 D435, 시리얼 261322075477, 펌웨어 5.15.1.55
- 스트림: 컬러 640x360 BGR8, 뎁스 424x240 Z16, 둘 다 30 fps. 뎁스는 정렬하지 않은 원본이다.
- 장면: 로봇은 정지해 있고 박스(205 mm 정사각, 높이 70 mm)를 앞에 놓았다. 갭을 80 → 10 mm 순서로 줄여 가며 놓았다.
- 구간 표시는 bag에 없다. 정지 구간은 시계열에서 찾아야 한다.
  - 계획은 갭당 3 s였지만, 실제로는 갭당 대략 4~6 s씩 놓였다.
  - 0~4 s에는 박스가 검출되지 않는다.
  - 녹화 PC에서 2 fps로 돌려 본 dx(mm)는 아래와 같다. 구간 경계는 참고만 하고 직접 다시 찾는다.

| 시간 (s) | dx (mm) |
|---|---|
| 9~18 | 70~83 |
| 19~21 | 58~68 |
| 22~27 | 52~57 |
| 28~33 | 39~50 |
| 35~41 | 33~38 |
| 42~46 | 25~29 |
| 47~48 | 31~34 (잠깐 튀었다) |
| 49~53 | 15~21 |
| 54~61 | 7~15 |

- 80→10 갭 8개와 정지 구간이 1:1로 깔끔하게 맞지 않을 수 있다. 맞추기 애매한 구간은 억지로 붙이지 않는다. 무엇이 애매한지 보고에 적는다.

## 4. 해야 할 일

### 4.1 환경

```bash
python3 -m venv venv && . venv/bin/activate
pip install numpy scipy opencv-python matplotlib
```

### 4.2 프레임 추출

```bash
python3 code/read_bag.py . --step 3        # 10 fps -> frames/t<ms>_{color.ppm,depth.u16,meta.txt}, 약 600장
```

`read_bag.py`가 하는 일:

- 컬러 프레임마다 수신 시각이 가장 가까운 뎁스 프레임을 붙인다(20 ms 이내).
- 뎁스를 `rs2::align(COLOR)` 규칙으로 컬러 격자에 정렬한다. 뎁스 픽셀 네 모서리를 투영하고, 덮인 컬러 픽셀 중 가까운 값을 남긴다.
- 녹화 PC에서 librealsense align과 비교한 결과:
  - 평탄면 픽셀의 93%가 완전히 같다.
  - 5 mm 넘게 다른 픽셀은 0.4%뿐이다(이웃 뎁스 픽셀이 이긴 경우).
  - 깊이 경계에서는 차이가 조금 더 크다.

### 4.3 거리 계산

프레임마다 아래처럼 계산한다. `lens_y=0.0322`가 로봇의 라이브 화면(box_live.py)과 같은 설정이다.

```python
import box_range as br            # sys.path에 code/ 추가
r = br.analyse_urdf(prefix, 'code/v307_full_robot.urdf', 0.0322)
# r['near'] = 박스 윗면 앞 모서리 중심 (x1,y1,z1), r['laser'] = front_laser (x0,y0,z0), r['xy'] = 답 [m]
dx = r['near'][0] - r['laser'][0];  dy = r['near'][1] - r['laser'][1]
```

- 박스를 못 찾으면 `RuntimeError`가 난다. 그 프레임은 `ok=0`과 오류 문구로 남긴다.
- `analyse_urdf`는 결과를 print한다. 필요하면 stdout을 막는다.

### 4.4 구간 나누기와 잔차표

- dx 시계열에서 정지 구간(평탄 구간)을 찾고 갭 80, 70, …, 10에 대응시킨다.
- 구간 양끝 0.3 s는 손이나 이동이 섞일 수 있으니 버린다.
- 갭별로 한 줄씩 아래 열을 만든다.

`gap_mm, t_start, t_end, n, fail, dx_median, dx-gap, xy_median, xy-gap, dy_median, sd_dx, min_dx, max_dx`

- 기준 비교: `code/series2.csv`의 `x_err_mm`(= x1−x0 − 테이프 갭)과 이번 `dx-gap`을 같은 표에 나란히 둔다.
  - series2의 `x_err_mm`은 −9.3 ~ +0.8 mm였고, 평균은 대략 −4 mm다.

## 5. 좌표와 URDF 정보

### 5.1 URDF (`code/v307_full_robot.urdf`)

- 좌표계는 REP-103이다. x 앞, y 왼쪽, z 위, 단위는 m와 rad다.
- `base_link` 원점은 네 바퀴 축의 중심이다(CAD (129, 228, −4.25) mm).
- 광학 프레임은 z가 시선, x가 오른쪽, y가 아래다.
- 아래 관절은 모두 fixed이고 parent는 `base_link`다.

| child 링크 | xyz [m] | rpy [rad] |
|---|---|---|
| `base_footprint` (바닥) | (0, 0, −0.034346) | (0, 0, 0) |
| `front_laser` | (0.19067, 0.00002, 0.0567) | (0, 0, 0) |
| `rear_laser` | (−0.11567, 0, 0.0507) | (0, 0, π) |
| `imu_link` | (−0.0355, 0.0895, 0.03512) | (0, 0, 0) |
| `camera_top_color_link` | (−0.0621011, −0.0325, 0.5928470) | (0, 0.760951, 0) → 숙임 43.6° |
| `camera_top_color_optical_frame` | (−0.0621011, −0.0325, 0.5928470) | (−2.331747, 0, −1.570796) |
| `camera_top_depth_link` | (−0.0620532, +0.0325, 0.5928611) | (0, 0.760951, 0) |
| `camera_top_depth_optical_frame` | (−0.0620532, +0.0325, 0.5928611) | (−2.331747, 0, −1.570796) |

- 그 밖의 관절:
  - 팔: `lm_slide`, `shoulder`, `elbow`, `wrist_pitch`, `tool_roll`, 집게 2개
  - `carousel`
  - 바퀴 4개: (±0.098, ±0.144, 0)
  - 손목 카메라 `camera_wrist_*`는 `wrist_pitch_link`에 붙어 있다.
- 이 작업에서는 위 표의 값만 쓴다.

### 5.2 URDF 위에 덧씌우는 실측 보정 (box_range.py / box_live.py 기본값)

URDF 파일은 고치지 않는다. 계산할 때 아래 값으로 바꿔 쓴다.

| 항목 | URDF | 사용 값 | 근거 |
|---|---|---|---|
| 컬러 렌즈 y | −0.0325 | **+0.0322** | D435 데이터시트 337029-005 표 4-15와 공장 외부 파라미터. 렌즈는 몸체 중심(=LiDAR 중심 선)에서 왼쪽 32.2 mm에 있다. URDF는 좌우가 뒤집혀 있는 것으로 보인다 |
| 렌즈 높이(바닥 기준) | 0.6271 | **0.6229 m** → base_link z = −0.034346 + 0.6229 = 0.588554 | 사용자 삼각측량(변 86 / 64.4 / 62.5 cm). 뎁스 바닥 평면 맞춤은 0.6265~0.6268 m |
| 카메라 yaw | 0 | **+1.5°** (왼쪽 +, 렌즈 위치를 축으로 base z 회전) | 섀시 −7.9°, 카메라 −6.4° 실측 |
| 숙임 | 43.6° | 43.6° | 사용자 실측. URDF와 같다 |

- 따라서 쓰는 카메라 포즈는 다음과 같다.
  - 위치: `t = (−0.0621011, +0.0322, 0.588554)`
  - 회전: `R = Rz(1.5°) · R_urdf(optical)`
- 구현은 `box_range.analyse_urdf()`에 있다(`lens_y`, `yaw_deg`, `cam_height` 인자).

### 5.3 카메라 내부 파라미터 (`meta.json`)

- 컬러 640x360: fx 454.191, fy 453.930, ppx 321.839, ppy 194.422, 왜곡 0
- 뎁스 424x240: fx = fy 212.073, ppx 214.373, ppy 121.235, 왜곡 0, depth_scale 0.001
- 뎁스→컬러 외부 파라미터: translation (0.014736, 0.000123, 0.000380) m
  - rotation 9개 값은 librealsense 규약대로 열 우선(column-major)이다. `reshape(3,3).T`로 써야 한다.

### 5.4 전면 LiDAR (`lidar/`이 있을 때)

시간 맞추기:

- 카메라 db3의 timestamp는 녹화 시작 = 0 ns다.
- `meta.json`의 `start_epoch`는 그 0의 벽시계 시각(초)이다.
- LiDAR bag의 timestamp는 epoch ns다.
- 따라서 `카메라 epoch = start_epoch + db3_ts / 1e9`로 맞춘다. 오차는 수십 ms 수준이다.

LiDAR TF(`/tf_static`, `lidar_processor.launch.py`가 내보내는 값)는 base_link → `laser_front` = xyz (0.155, 0, 0.021), yaw 180°, roll 180°다.

- LiDAR는 거꾸로 달려 있다(업사이드다운). roll 180° 때문에 스캔 각도의 부호가 뒤집힌다.
- 이 TF의 base_link는 실제 회전 중심이다. 2026-10-16에 퍽으로 보정한 값이다.
- URDF의 base_link(네 바퀴 축 중심)와 `front_laser` (0.19067, 0.00002, 0.0567)와는 정의가 다르다. 두 값을 섞지 않는다.
- LiDAR 점을 카메라 결과와 비교할 때는 어느 기준을 썼는지 적는다.

LiDAR로 할 일:

- 박스 앞면(높이 70 mm)이 스캔 평면에 걸려 잡히는지 먼저 확인한다.
- 잡히면 정면(±10°) 최소 거리를 시계열로 뽑아 카메라 dx와 같은 시간축에 그린다.
- LiDAR 거리 − 테이프 갭의 오프셋, 갭별 sd, 카메라와의 차이를 4.4절 표에 열로 더한다.

## 6. 측정 정의

- 박스: 윗면 205 mm 정사각, 높이 70 mm
- 갭: LiDAR 앞면에서 박스 앞 모서리까지, 바닥을 따라 앞 방향으로 잰 거리다. 테이프로 맞췄다.
- 답: `|(x1,y1) − (x0,y0)|`, base_link 기준이고 z는 무시한다.
  - (x0,y0) = `front_laser` 원점
  - (x1,y1) = 박스 윗면 앞 모서리의 중심
  - 갭과 직접 비교하는 값은 `dx = x1 − x0`다(series2의 `x_err_mm`과 같은 정의). `xy`는 dy가 섞인 값이다.
- 박스가 로봇 정면에서 옆으로 틀어져 있으면 dy가 0이 아니다. dy는 참고로만 본다.

## 7. 알고리즘 요약 (`box_range.analyse_urdf`)

1. 뎁스를 3D로 바꾼다. 영상 아래쪽 절반만 쓴다.
2. 높이 사전값으로 박스 후보 픽셀을 고른다. 높이 = 카메라 높이 + up·P, 70 ± 30 mm.
3. RANSAC으로 윗면 평면을 찾는다.
   - 인라이어 5 mm, 기울기 8° 이내, 높이 오차 30 mm
   - 면적 0.4~1.4 × 205²
   - 500회 반복 후 재맞춤
4. 윗면 외곽에 최소 면적 사각형을 맞춘다. 모서리는 뎁스가 윗면보다 10 mm 떨어지는 곳이다(`edge_drop` 0.010).
5. 앞 모서리가 로봇이나 영상 경계에 가려졌을 수 있다.
   - 앞 모서리 = 먼 모서리 − 205 mm로 둔다.
   - 먼 모서리 두 개가 다 보이면 그 중점을 쓴다.
   - 하나가 가려졌으면 보이는 모서리에서 102.5 mm 안쪽을 쓴다(아직 실측 검증 전).
6. 사각형을 base_link로 옮기고 위 6절의 답을 계산한다.

이전 정지 사진 시리즈에서 `edge_drop` 0.010 기준의 x 오차는 평균 −0.9 mm, sd 2.5 mm, 폭 204 mm였다.

## 8. 하지 말 것

- URDF 파일을 수정하지 않는다. 보정은 5.2절의 인자로만 넣는다.
- 기본 설정 결과를 바꾼 설정 결과로 덮어쓰지 않는다.
- 원본 `boxgap.db3`, `meta.json`을 수정하지 않는다.
